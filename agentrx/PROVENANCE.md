# Provenance of the numbers in `AUTOPSY.md`

`AUTOPSY.md` is generated by `agentrx.py record` — nothing in it is typed by hand. This file
records the things a generated report cannot know about itself, so that anyone reading the
numbers knows exactly what produced them.

## What the recorded run measured

| | |
|---|---|
| Baseline (train, T-4471) | resolved 0/3, cost $0.3791 |
| Final (train, T-4471) | resolved 3/3 |
| Holdout (T-4490, T-4503 only) | resolved 6/6 |
| Patient tools | 17 → 17 |
| Iterations | 1 |

The holdout number is **holdout-only**. The harness runs train and holdout tickets together and
prints one grand total across all three tickets — 9/9 on this run. That total includes T-4471, the
ticket the patch was fitted to, so reporting it as a holdout score would inflate the
generalization claim by a third and print an impossible denominator for two tickets at three
trials. `agentrx._split_holdout()` sums the per-ticket rows from the harness's own `runs.jsonl`
instead, and parks the grand total under `mixed_resolved_trials` where no consumer can render it
as "holdout".

**The holdout ran separately.** The first attempt died when the sandbox was emptied mid-flight,
three trials deep and already paid for. `rerun_holdout.py` recovered it: it rebuilds the pristine
broken patient, re-applies the recorded patch **verbatim** from `artifacts/full_run.json`,
verifies the change landed by re-reading the file from disk, and only then runs the holdout. It
re-runs the *evaluation*, never the *diagnosis* — the swarm's findings are not reconsidered and
nothing in that script can improve the recorded result.

The two bugs that made that wipe possible are both fixed: the run lock's liveness probe now fails
closed, and `reset()` builds a staging copy and swaps it in atomically rather than emptying the
live directory first.

## What the recorded run does NOT support

**Tools went 17 → 17.** The Attending explicitly deferred the tool removals its Tool-Spec
specialist proposed; the only change that landed was the prompt patch. Nothing claims otherwise,
but the obvious question — *what did the other two specialists actually buy you?* — has an honest
answer: on this run, findings the coordinator chose not to act on.

**The prompts have changed since this recording.** A review found that the specialist system
prompts and their attached playbooks used this patient's own planted defects as worked examples,
and that each playbook's closing section named the other two lanes. Both are fixed, and
`tests.py` now pins both. But that means **the agents that produced the numbers above were not as
blind as the ones in this repo now are** — they carried scaffolding the current prompts do not.
Re-run `record` to get numbers that match the committed prompts.

**Per-round context growth is not measured.** The loop is single-round and each iteration opens a
fresh session, so the unbounded-growth curve this build would most like to show has never been
instrumented. `selfcheck` lists it under UNVERIFIED for that reason.

## Reproducing

```
python agentrx.py --trials 3 --iterations 2 --holdout record
```

Real API calls, several minutes, a few dollars. Every stage checkpoints to `artifacts/`, so a
late failure never discards the baseline or the briefs. `artifacts/` is gitignored — it is one
account's billed run, not source — so `demo` has nothing to replay on a fresh clone until you
have run `record` once.
